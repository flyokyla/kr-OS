polybar

Быстрая и легко настраиваемая панель статуса для оконных менеджеров. Отображает информацию о системе в компактной строке на краю экрана.

Производитель Сообщество polybar (Michael Carlberg и др.)
Сайт polybar.github.io
Лицензия MIT

Возможности и особенности

Polybar — инструмент для создания статусных панелей, особенно востребованный в оконных менеджерах с ограниченной или отсутствующей встроенной панелью, таких как i3wm, bspwm и awesome. Программа написана на C++ и ориентирована на простоту конфигурации без необходимости писать shell-скрипты.

  • Встроенные модули для отображения: рабочих пространств i3/bspwm, даты и времени, уровня громкости (PulseAudio/ALSA), яркости экрана, заряда батареи, сетевого подключения, температуры CPU и загрузки ОЗУ
  • Поддержка пользовательских скриптов — можно выводить любую информацию через модуль custom/script
  • Полная настройка внешнего вида: шрифты, цвета, отступы, разделители, прозрачность
  • Поддержка нескольких мониторов с возможностью размещения разных панелей на каждом
  • Кликабельные элементы — модули могут реагировать на нажатия мышью и запускать команды
  • Системный трей (system tray) для отображения иконок приложений
  • IPC-интерфейс для управления панелью из внешних скриптов

Конфигурация производится через INI-файл ~/.config/polybar/config.ini, что делает настройку интуитивно понятной даже без глубоких технических знаний.

Создание пользовательского модуля скрипта

Задача: создать модуль, отображающий количество доступных обновлений пакетов Arch Linux.

Шаг 1. Создаём скрипт ~/.config/polybar/scripts/updates.sh:

updates=$(checkupdates 2>/dev/null | wc -l)

    echo "$updates обн."
else
    echo "Актуально"
fi

Вывод

Polybar — незаменимый инструмент для создания информативной и красивой панели статуса в тайловых оконных менеджерах. Благодаря модульной архитектуре и простому формату конфигурации, панель легко адаптируется под любые потребности пользователя.

Плюсы

  • Высокая производительность благодаря реализации на C++
  • Богатый набор встроенных модулей
  • Простой INI-формат конфигурации
  • Активное сообщество с множеством готовых тем

Минусы

  • Работает только с X11, нет поддержки Wayland
  • Требует ручной настройки — нет GUI-конфигуратора
  • Некоторые модули могут потребовать дополнительных зависимостей

htop

Кросс-платформенный интерактивный просмотрщик процессов — улучшенная альтернатива стандартной утилите top.

Производитель Hisham Muhammad (автор), сообщество htop-dev
Сайт htop.dev
Версия 3.4.1

Возможности

htop — интерактивный просмотрщик процессов, разработанный Hisham Muhammad в 2004 году. С 2020 года проект поддерживается командой разработчиков на GitHub. В отличие от стандартного top, htop предоставляет полноцветный интерфейс с поддержкой мыши и горизонтальной/вертикальной прокрутки.

  • Отображение всех процессов в виде дерева или плоского списка
  • Цветовые индикаторы загрузки CPU, оперативной памяти и swap
  • Сортировка процессов по CPU, памяти, приоритету, времени работы и другим параметрам
  • Поиск и фильтрация процессов в реальном времени
  • Отправка сигналов процессам (kill, stop, continue) прямо из интерфейса

Особенности

htop отличается от стандартного top наличием полноценного TUI (Text User Interface), что делает работу с процессами интуитивной и быстрой.

  • Поддержка мыши — можно кликать по заголовкам столбцов для сортировки
  • Настраиваемые метрики в верхней части экрана (meters)
  • Древовидное отображение процессов с визуализацией иерархии родитель-потомок
  • Кросс-платформенность — работает на Linux, FreeBSD, macOS и других Unix-системах
  • Изменение приоритета (nice) процессов без выхода из программы

Вывод

htop — один из самых популярных инструментов мониторинга процессов в Linux. Благодаря цветному интерфейсу, поддержке мыши и интуитивному управлению, htop значительно упрощает диагностику загрузки системы и управление процессами.

Плюсы

  • Наглядный цветной интерфейс с индикаторами загрузки
  • Поддержка мыши и клавиатурного управления

  • Работает только в терминале, нет графического интерфейса
  • Не сохраняет историю метрик для последующего анализа
  • Ограниченные возможности мониторинга сети и дисков

Glances

Кросс-платформенный инструмент комплексного мониторинга системы, написанный на Python. Альтернатива top/htop с расширенным набором метрик.

О программе

Производитель Nicolas Hennion (nicolargo)
Сайт nicolargo.github.io/glances
Версия 4.5.2

Возможности

Glances — инструмент мониторинга системы, разработанный Nicolas Hennion и написанный на Python. В отличие от htop, который фокусируется на процессах, Glances предоставляет комплексный обзор всех аспектов работы системы на одном экране.

  • Мониторинг CPU, оперативной памяти, swap, дискового пространства и сетевых интерфейсов
  • Отображение процессов с сортировкой по автоматически определяемому «узкому месту»
  • Мониторинг температуры датчиков, скорости вентиляторов и напряжения
  • Отслеживание ввода-вывода дисков и сетевого трафика в реальном времени
  • Поддержка мониторинга Docker-контейнеров
  • Встроенный веб-интерфейс для удалённого мониторинга через браузер
  • REST API для интеграции с другими системами
  • Экспорт данных в CSV, InfluxDB, Elasticsearch, Prometheus и другие хранилища

Особенности

Glances выделяется среди инструментов мониторинга своей универсальностью и множеством режимов работы:

  • Standalone-режим — классическое отображение в терминале
  • Веб-режим — запуск через glances -w открывает веб-интерфейс на порту 61208
  • Клиент-серверный режим — мониторинг удалённых машин через сеть
  • Цветовая индикация: зелёный (OK), синий (осторожно), фиолетовый (предупреждение), красный (критическое)
  • Кросс-платформенность: Linux, macOS, FreeBSD, Windows
  • Установка одной командой: pip install glances или sudo pacman -S glances

Эксперименты

Эксперимент 1
Запуск Glances в режиме терминала

Задача: запустить Glances и изучить основной интерфейс мониторинга в терминале.

Действия: установлен Glances: sudo pacman -S glances. Запущен командой glances. Изучены доступные секции интерфейса и горячие клавиши (вызываются по h).

Результат: на одном экране терминала отображается комплексная информация: загрузка CPU по ядрам, использование RAM и swap, список процессов (отсортированных по автоматически определяемому «узкому месту»), дисковый ввод-вывод, сетевой трафик по интерфейсам, температура датчиков. Цветовая индикация работает: зелёные значения — норма, фиолетовые — предупреждение, красные — критические.

Эксперимент 2
Запуск веб-интерфейса мониторинга

Задача: запустить Glances в режиме веб-сервера для удалённого мониторинга через браузер.

Действия: установлен дополнительный модуль: pip install glances[web]. Запущен веб-режим: glances -w. В браузере открыт адрес http://localhost:61208.

Результат: в браузере отобразился полноценный дашборд мониторинга с теми же данными, что и в терминальной версии. Веб-интерфейс обновляется автоматически каждые несколько секунд. Интерфейс адаптивный — корректно отображается на мобильных устройствах. Доступ по сети: с другого компьютера по адресу http://192.168.1.100:61208 дашборд также доступен.

Эксперимент 3
Мониторинг дискового ввода-вывода

Задача: отследить нагрузку на дисковую подсистему при копировании большого файла.

Действия: запущен Glances. В отдельном терминале запущено копирование большого файла: dd if=/dev/zero of=~/testfile bs=1M count=1024 (создание файла размером 1 ГБ). В Glances нажата клавиша d для включения секции Disk I/O.

Результат: в секции «DISK I/O» отобразился резкий рост скорости записи на устройство sda: ~350 МБ/с при записи. Значение подсвечено фиолетовым (предупреждение о высокой нагрузке). После завершения dd скорость записи вернулась к нулю. Чтение оставалось минимальным на протяжении всего эксперимента. Glances также показал процесс dd в топе по дисковому вводу-выводу.

Эксперимент 4
Мониторинг сетевого трафика

Задача: отследить сетевой трафик при загрузке файла из интернета.

Действия: в Glances нажата клавиша n для отображения секции Network. В отдельном терминале запущена загрузка: curl -O https://releases.ubuntu.com/22.04/ubuntu-22.04-desktop-amd64.iso.

Результат: в секции «NETWORK» для интерфейса wlan0 отобразился входящий трафик ~12 МБ/с (Rx), исходящий — минимальный (Tx). Значения обновляются в реальном времени. При паузе загрузки трафик падает до нуля, при возобновлении — снова растёт. Glances корректно различает трафик по разным сетевым интерфейсам (wlan0, lo).

Эксперимент 5
Экспорт данных мониторинга в CSV

Задача: сохранить данные мониторинга в CSV-файл для последующего анализа.

Действия: Glances запущен с параметром экспорта: glances --export csv --export-csv-file /tmp/glances_report.csv. Программа работала в течение 5 минут, собирая данные каждые 3 секунды.

Результат: после остановки Glances (Ctrl+C) создан файл /tmp/glances_report.csv размером около 800 КБ. Файл содержит столбцы: timestamp, cpu_percent, mem_percent, swap_percent, disk_read, disk_write, net_rx, net_tx и другие метрики. Данные можно импортировать в Excel или обработать скриптом на Python для построения графиков нагрузки за период наблюдения.

Вывод

Glances — мощный и универсальный инструмент мониторинга, который предоставляет максимально полную картину состояния системы. Благодаря веб-интерфейсу и REST API, Glances подходит как для локального, так и для удалённого мониторинга серверов и рабочих станций.

Плюсы

  • Комплексный мониторинг всех подсистем на одном экране
  • Встроенный веб-интерфейс и REST API
  • Экспорт данных в различные системы хранения
  • Мониторинг Docker-контейнеров
  • Кросс-платформенность

Минусы

  • Более высокое потребление ресурсов из-за Python
  • Требует установки дополнительных зависимостей для некоторых функций
  • Менее детальная информация по процессам по сравнению с htop

Общий вывод по разделу

Рассмотренные инструменты дополняют друг друга и решают разные задачи мониторинга в Arch Linux:

  • polybar — постоянная панель статуса, отображающая ключевые метрики системы в реальном времени прямо на рабочем столе;
  • htop — детальный анализ процессов с возможностью управления ими (завершение, изменение приоритета);
  • Glances — комплексный мониторинг всех подсистем с возможностью удалённого доступа через веб-интерфейс.

Для повседневного использования рекомендуется связка polybar (для постоянного отображения базовых метрик) + htop (для диагностики проблем с процессами). Glances целесообразно использовать для глубокого анализа нагрузки на систему, а также для удалённого мониторинга серверов благодаря встроенному веб-серверу.
